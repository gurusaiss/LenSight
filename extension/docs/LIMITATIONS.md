# Limitations matrix

Matches the research doc's Platform Capability Matrix (L1–L7) and MVP scope.
No fake functionality: anything not listed as Implemented does not run.

## Known build-time caveat

**Updated (DEP-01, 2026-10-05).** Builds before DEP-01 emitted two `eval`
warnings, one from `pdfjs-dist@3`'s legacy build and one from the
`onnxruntime-web` bundled by `@xenova/transformers@2`. After the upgrade to
`pdfjs-dist@6.4.299` and `@huggingface/transformers@4.3.0` (with
`onnxruntime-web/wasm`), `npm run build` emits **no** `eval` warning, and the
built `background.js` contains no `eval(` call and no `new Function(`. The
only `Function("return this")` left is core-js's `globalThis` detection
fallback, which is never reached because `self` exists in a service worker.

`background.js` is ~2.33 MB. pdf.js 6.x's worker module is now bundled into
it, because the MV3 service worker can't spawn a Web Worker or `import()` one
at runtime (see `pdfAdapter.ts`). ONNX Runtime's Emscripten loader is
embedded too. The model weights (tens of MB) are **not** part of the bundle.
They are fetched from Hugging Face only if a user selects the
Transformers.js embedding option.

## 2026-09-24 audit/remediation pass — what changed in this matrix

See `../REMEDIATION_REPORT_ai-context-assistant_2026-09-24.md` (scratchpad
root) for the full issue registry. Capability-relevant changes:

| Capability | Status | Notes |
|---|---|---|
| Page/selection capture on any tab | **Implemented — now requires invoking the extension on the tab** | The content script is no longer injected into every site. The side panel injects it on demand via `chrome.scripting.executeScript` under the `activeTab` grant, which Chrome gives when you click the toolbar icon or use a shortcut on that tab. If access is missing (e.g. after navigating the tab), capture shows an actionable "click the toolbar icon" message. Also fixes tabs that were open before install/update ("Receiving end does not exist"). Verified by unit tests with a mocked `chrome.tabs`/`chrome.scripting`; not exercised in a real browser here. |
| Retrieval scope "Current source only" | **Implemented (was broken)** | The side panel never sent the current source id, so questions searched every source ever captured (and in Mode B sent unrelated chunks to the remote provider). Fixed; the background now rejects unscoped questions. |
| Transformers.js embeddings in the packaged extension | **Runtime pipeline verified in real Chromium with a synthetic model. Real-model quality still unverified** | Before: the CSP lacked `'wasm-unsafe-eval'` (WASM could not instantiate) and onnxruntime-web fetched its `.wasm` from cdn.jsdelivr.net (remote code, blocked by CSP and disallowed by CWS policy). **DEP-01 (2026-10-05):** migrated to `@huggingface/transformers@4.3.0`. `onnxruntime-web/webgpu` is aliased to the CPU-only `onnxruntime-web/wasm` bundle, which embeds its loader, so the service worker never needs `import()`. One binary ships, `ort/ort-wasm-simd-threaded.wasm` (14.26 MB; the package total went from 20.77 MB to 16.84 MB), and `configureTransformersEnv()` points ORT at it with `wasmPaths: { wasm }`, single-threaded. The library's CDN default block is stripped from its source at build time, so `cdn.jsdelivr.net` no longer appears anywhere in `.output/chrome-mv3/`. The build now fails if it ever reappears.
